# 개인 프로젝트 초기 설정

사용자의 개인 표준 `base`를 재사용해 프로젝트 뼈대를 만든다. 기존 `project-init` 스킬과 독립적으로 동작한다. 이 스킬은 스택이나 실행환경을 자동으로 선택하지 않는다.

## 기준과 범위

- 생성 전에 [assets/AGENTS.md](assets/AGENTS.md)를 읽는다. 새 프로젝트의 규약으로 복사할 원본이다. 원본 위치와 실측 결과는 [references/base-analysis.md](references/base-analysis.md)에 있다.
- 대화와 최종 보고는 한국어, 내부 문서는 기본 영어다. 사용자의 명시적 언어 선택을 우선한다.
- 기본 구조는 루트 `AGENTS.md`, `README.md`, `.gitignore`, `docs/DECISIONS.md`, `docs/MEMORY.md`, `docs/STRUCTURE.md`, `src/`, `out/`이다. 비어 있는 `src/`와 `out/`은 `.gitkeep`으로 보존한다.
- 사용자가 지정한 서브레포만 루트에 생성하고 각각 README를 둔다. 모노레포 규칙이 있다고 해서 `api/client/app/db`를 일괄 생성하거나 중첩 Git 저장소를 초기화하지 않는다.
- 뼈대 생성에 도구 설치, Git 초기화, 의존성 설치, 모델 다운로드는 포함되지 않는다. 함께 요청된 경우 명시된 범위에서 별도 작업으로 처리하고 스택에 맞는 스킬을 사용한다.

## 작업 절차

1. 대상 절대 경로와 기존 파일을 확인한다. `.DS_Store`, `Thumbs.db`, `.git/`, 비어 있는 디렉터리는 새 프로젝트 판정에서 무시한다. 심볼릭 링크 대상이나 기존 소스가 있는 프로젝트를 자동으로 재구성하지 않는다. 기존 파일이 있으면 충돌 경로를 제시하고, 요청이 기존 프로젝트 보완까지 포함하는지 확인한다. 기존 파일 삭제나 덮어쓰기를 전제로 진행하지 않는다.
2. 대화에서 대상 경로, 프로젝트명, 설명, 서브레포 구성과 확정된 스택을 추출한다. 이미 알려진 내용을 재질문하지 않는다. 이름은 별도 지정이 없으면 대상 폴더명을 사용한다. 설명과 실행법이 미정이면 `TBD`, 지정하지 않은 서브레포는 `None confirmed`로 기록한다. 대상 경로가 불명확하거나 상충하는 선택만 질문한다.
3. 생성할 파일 경로 전부를 먼저 점검한다. 기존 파일과 충돌하면 해당 파일을 임의로 바꾸지 않는다. 생성 경로가 프로젝트 밖으로 벗어나지 않도록 서브레포 이름을 확인한다. 참조 `base` 폴더와 기존 스킬은 수정하지 않는다.
4. `assets/AGENTS.md`를 복사한다. 유일한 기본 치환은 `Per-language conventions` 표의 `_None confirmed_` 행을 지정된 서브레포 행으로 바꾸는 것이다. 확정되지 않은 언어·명명·타입 표기는 `TBD`로 유지한다. 사용자가 별도의 규칙 수정을 요청한 경우 그 변경을 명시하고 반영한다.
5. 아래 문서 요구사항대로 파일을 작성한다. `.gitignore`는 OS 메타데이터, 선택한 도구의 캐시와 비밀값 파일을 제외하도록 구성한다. `out/*`와 `!out/.gitkeep`을 포함하며 `.env.example`은 보존한다. 스택 미정 상태에서는 소스 경로나 의존성 잠금 파일을 광범위하게 제외하지 않는다.
6. 모든 파일을 만든 뒤 실제 트리를 읽어 `docs/STRUCTURE.md`를 완성한다. `.git/` 내부와 OS 메타데이터는 구조 트리에서 제외한다. 외장 SSD 경로도 그대로 대상 경로로 사용할 수 있다. SSD에 새 가상환경이 필요하면 별도 요청 범위에서 생성하며 다른 위치의 가상환경을 복사하지 않는다.

## 문서 요구사항

- 루트 README: 프로젝트 요약, 구조, 전체 스택 실행 안내, docs 상대 링크. 확정된 실행 명령만 작성하며 미정 사항은 `TBD`로 표시한다.
- 서브레포 README: 해당 구성의 역할과 실행/테스트 안내. 미정 사항은 `TBD`로 표시한다.
- DECISIONS: 날짜, 결정, 이유와 영향을 기록하는 원장. 초기 `docs/src/out` 선택과 지정된 서브레포 구성을 실제 사실에 근거해 기록한다. 날짜는 사용자의 현지 날짜를 사용한다.
- MEMORY: 짧고 검색 가능한 참조, 확인된 제약과 미정 항목. 장문의 결정 설명을 중복하지 않는다.
- STRUCTURE: 생성 후 실측한 트리와 경로별 목적. `src/`는 루트 또는 공통 소스, `out/`은 생성 산출물, `docs/`는 프로젝트 문서로 설명한다. 존재하지 않는 폴더를 넣지 않는다.
- Testing 규칙은 AGENTS 원문대로 보존한다. 뼈대만 만든 시점에는 테스트 러너와 100% 커버리지 검증을 `Pending: no application code or test runner yet`로 기록한다. 검증하지 않은 커버리지를 달성했다고 쓰거나 항상 통과하는 테스트를 만들지 않는다.

## 완료 확인과 보고

생성 파일 누락, Markdown 상대 링크, 미치환 템플릿 변수, STRUCTURE와 실측 트리의 일치 여부를 확인한다. AGENTS는 서브레포 표 또는 사용자가 요청한 변경 외에는 번들 원문과 같아야 한다. 코드·주석·문서에 사용자가 요청하지 않은 이모지를 넣지 않는다.

최종 답변은 생성 프로젝트 규약에 따라 `[USED: skill:personal-project-init(files: 실제 읽은 스킬 파일 경로들)]` 한 줄로 시작한다. 생성 위치와 주요 파일, 실제 검증 결과, 미정인 실행환경을 한국어로 짧게 보고한다. 스킬 파일에 적힌 예제 경로를 실제 사용 경로인 것처럼 보고하지 않는다.
